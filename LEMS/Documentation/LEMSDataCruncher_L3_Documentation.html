LEMSDataCruncher_L3 Documentation

Data Processing Pipeline — Detailed Workflow & File Specifications for Steps 1 through 33 (L2 Reprocessing, Group Analysis, L3 Comparisons & Plotting)

Session Initialization & Folder Selection

When running LEMSDataCruncher_L3.py, you will first choose between:

  • CLI Mode (cli): You are prompted for a root folder_path. The folder must contain UnformattedDataL2FilePaths_DataEntrySheetFilePaths.csv, which links to each group’s DataEntrySheetFilePaths.csv and lists the test paths.
  • GUI Mode (default): You enter the number of test runs and select each test’s Data Entry Form via file picker dialog ([testname]_TE_DataEntryForm.xlsx). The target folder is determined from the directory where the selected file lives.
  • Execution Mode: Choose 1 for Interactive Mode (plots open in Matplotlib, popups prompt for inputs) or 2 for Reprocessing Mode (runs in parallel across worker processes, non-interactive, reads existing parameters).

Core Master Manifest: UnformattedDataL2FilePaths_DataEntrySheetFilePaths.csv

Located in the root project folder (folder_path), this CSV acts as the master index and dependency backbone for the entire LEMS pipeline. It binds multi-test groups together and establishes the primary data hierarchy across steps:

  • Columns Supported (case-insensitive):
    • Name: Human-readable group/stove name (e.g. Three-Stone Fire, Rocket Stove). Primary source for plot labels and report headers.
    • Code: Short group code (e.g. TSF, RKT). Secondary fallback for plot labels.
    • Path: Full path to that group’s DataEntrySheetFilePaths.csv (e.g. C:\Data\Group1\DataEntrySheetFilePaths.csv).
  • Pipeline Dependencies:
    • Per-Test Steps 1–15: LEMS reads each group’s DataEntrySheetFilePaths.csv to discover all individual test paths (list_input).
    • Group Comparison Steps 16–19: Defines group boundaries and directory targets (list_groups) for writing UnFormattedDataL2.csv and FormattedDataL2.csv.
    • L3 Comparison & Plotting Steps 20, 23–30: Automatically locates each group’s UnFormattedDataL2.csv (located in the same directory as the group CSV) and populates list_input_L3 and list_labels_L3.

Step 1 plot raw data

Plots all raw time-series sensor channels against time. Verifies signal continuity, timestamps, and data validity before running calculations.

Target Folder File Prerequisites

User Decisions & Inputs Required

1. Channel Selection & Scaling in [testname]_rawplots.csv

When Step 1 runs for the first time, it discovers all plottable channels and writes [testname]_rawplots.csv with Plotted = 0 (disabled). To view specific channels:

  • Open [testname]_rawplots.csv in a text editor or spreadsheet program.
  • Set Plotted to 1 for any channel you want to display (e.g., CO, CO2, PM).
  • Adjust Scale multipliers as needed (e.g., 0.1 or 10) so channels with different magnitudes fit on one graph.
  • (Optional) Assign colors or numeric plot Order (higher values plot on top). Save the file and re-run Step 1.
2. Window Interaction (Interactive Mode 1)

An interactive Matplotlib window opens displaying the graph. The user inspects the raw data curves, zooms/pans as needed, and closes the window to finish the step and return to the main menu.

In Reprocessing Mode (2): Matplotlib runs headless (Agg backend). No user input is required; the image is generated directly.

Step 6 correct for response times

Shifts individual time-series sensor channels forward or backward along the time axis to compensate for sample line transit delays and differing sensor response times (e.g. aligning electrochemical or NDIR gas sensors with optical particulate sensors).

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_RawData_Recalibrated.csv Recalibrated time-series CSV produced by Step 5. (If Step 5 was skipped, a copy of [testname]_RawData.csv named with this pattern must be present).
Optional / Auto-Created [testname]_TimeShifts.csv Channel time shift configuration table. If not already present in the folder, the script automatically creates it with 0 seconds for every channel.

User Decisions & Inputs Required

Configuring Time Delay Offsets (Interactive Mode 1)

A multi-entry dialog (easygui.multenterbox) titled Gitrdone opens displaying each sensor channel (excluding light sensor AS channels and time columns) with its current shift in seconds.

User Decisions: Enter the number of integer seconds to shift each data channel:

  • Negative Values (e.g. -8): Shifts the data series back in time (advances signal; removes leading points and pads the end). Use this if a gas sensor lags behind real-time combustion events due to long sample tubing.
  • Positive Values (e.g. +5): Shifts the data series forward in time (delays signal; pads the front and truncates the end).
  • Zero (0): Leaves the channel unshifted.

Clicking OK applies the shift and updates [testname]_TimeShifts.csv.

Manual Alternative: You can open and edit [testname]_TimeShifts.csv directly in a text editor or spreadsheet prior to running Step 6.

In Reprocessing Mode (2): Bypasses the dialog and automatically applies shift values already saved in [testname]_TimeShifts.csv.

Step 7 subtract background

Determines ambient pollutant baselines before and after the test, inspects signal drift, and subtracts background levels from time-series sensor signals (CO, CO2, PM, VOC, CH4, and differential pressures). Generates phase-by-phase averages and background-subtracted time-series data.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_RawData_Shifted.csv Time-aligned time-series sensor data produced by Step 6.
Required [testname]_EnergyInputs.csv Test inputs table from Step 2, providing initial phase timestamps.
Optional / Auto-Created [testname]_PhaseTimes.csv Start and end timestamps for pre-background (prebkg), test phases (L1, hp, mp, lp, L5), and post-background (postbkg).
Optional / Auto-Created [testname]_BkgMethods.csv Channel-specific background subtraction method and numeric offset specification (e.g. prepostlin,0).
Optional / Auto-Created [testname]_UCInputs.csv Measurement uncertainty configuration table (absolute and relative uncertainties).

User Decisions & Inputs Required

1. Initial Background Times Prompt (Interactive Mode 1)

If [testname]_PhaseTimes.csv does not exist, an entry dialog opens asking for start and end times for pre-test and post-test background periods (start_time_prebkg, end_time_prebkg, start_time_postbkg, end_time_postbkg). Default values are suggested based on file start/end times.

2. Interactive Phase Time & Method Refinement Loop (Interactive Mode 1)

Two Matplotlib figures open displaying time-series curves (CO, CO2, PM) with vertical phase boundary markers. An interactive loop prompts the user through two dialogs:

  • Edit Phase Times Dialog: The user zooms into the plot to locate stable, flat baseline regions before stove ignition and after burnout, then enters refined start and end times for prebkg, test phases, and postbkg.
  • Edit Background Subtraction Methods Dialog: For each background channel, enter method,offset:
    • prepostlin: (Recommended) Linear interpolation between mean pre-background and post-background values to correct for instrument baseline drift.
    • prepoststave: Simple mean of pre- and post-background periods.
    • pre: Uses pre-test background average only.
    • post: Uses post-test background average only.
    • none: Disables background subtraction for that channel.
    • offset: Numeric value added to data after subtraction (normally 0).

Closing the plot windows accepts the current configuration and finishes the step.

In Reprocessing Mode (2): Bypasses interactive dialogs and plots, reading parameters directly from [testname]_PhaseTimes.csv and [testname]_BkgMethods.csv.

Defining Paired Mappings & Syntax Rules

PairsUnformattedDataL2FilePaths.csv serves two distinct roles in the same file: loading test data and instructing LEMS to compute differences between pairs.

  • Header Row: Must include columns Name, test_code, data_key, and path (case-insensitive).
  • Data Rows (Loading Tests):
    • data_key: Short identifier for the test (e.g. 1B for baseline, 1R1 for round 1).
    • path: Full path to that test group's UnFormattedDataL2.csv.
    • Name & test_code: Descriptive name and short label used on plots and headers.
  • Comparison / Difference Rows (Calculating Differences):
    • data_key: Must use difference syntax d<Initial>/<Final> or <Initial>/<Final> (e.g. d1B/1R1).
    • path: MUST BE LEFT BLANK. This empty path tells LEMS that this row is a calculation instruction rather than a data file to load.
    • When LEMS encounters d1B/1R1, it automatically computes:
      • % Change: ((avg_final - avg_init) / avg_init) * 100
      • 95% CI High & Low Bounds: using degrees of freedom N_init + N_final - 2 and pooled standard error.
  • Execution: Select menu option 22. The script calls LEMS_FormatData_L3Pairs to produce PairsFormattedDataL3.csv.

How Plotting Steps (23–29) Locate Data & Generate Plotting Order

Plotting steps in LEMS operate in two distinct modes depending on whether a pairs configuration file is present:

1. Standard Mode (When PairsUnformattedDataL2FilePaths.csv is NOT Present)

  • How LEMS Locates UnFormattedDataL2.csv Files:
    During startup in CLI mode, LEMS reads the master manifest:
    UnformattedDataL2FilePaths_DataEntrySheetFilePaths.csv (located in folder_path).
    For each row, it extracts the directory path containing that group’s DataEntrySheetFilePaths.csv (group_dir) and automatically points to:
    os.path.join(group_dir, 'UnFormattedDataL2.csv').
    These paths are stored in memory as list_input_L3.
  • How Plotting Order is Generated:
    The horizontal order along the x-axis strictly mirrors the top-to-bottom row order in UnformattedDataL2FilePaths_DataEntrySheetFilePaths.csv:
    • Row 1 in the manifest = Group 1 (leftmost position on x-axis).
    • Row 2 in the manifest = Group 2.
    • Row 3 in the manifest = Group 3, and so on.
  • How X-Axis Labels are Chosen:
    LEMS resolves labels (list_labels_L3) from UnformattedDataL2FilePaths_DataEntrySheetFilePaths.csv using this strict priority hierarchy:
    1. Name Column (highest priority): If present and non-empty, uses this text (e.g. Baseline 3-Stone).
    2. Code Column: If Name is absent or blank, uses the short code (e.g. TSF).
    3. Folder Name Fallback: If both are missing, defaults to the group’s directory folder name.

2. Paired Mode (When PairsUnformattedDataL2FilePaths.csv IS Present)

  • Overrides Standard Mode: If PairsUnformattedDataL2FilePaths.csv exists in folder_path, LEMS automatically loads list_input_pairs, list_labels_pairs, and list_pair_groups.
  • File Location: Locates each test’s UnFormattedDataL2.csv directly from the path column in PairsUnformattedDataL2FilePaths.csv.
  • Plotting Order & Shading: Follows the exact row order of tests in the pairs file. LEMS applies alternating gray background shading (#f2f2f2), vertical divider lines between pairs, and renders top-header boxes with pair group names.

File Retention, Deletion & Folder Structure Changes

1. Does Step 33 Delete Old Files?

NO. Step 33 NEVER deletes files from the destination directory.

  • Windows (robocopy): Uses flags /E /XO.
    • /E: Recursively copies subdirectories, including empty folders.
    • /XO: eXclude Older — prevents older local files from overwriting newer destination files.
    • Crucially, mirroring or purge flags (/PURGE, /MIR) are NOT used. Robocopy will strictly add or update files, never remove them.
  • macOS / Linux (rsync): Uses flags rsync -a <source>/ <dest>.
    • -a: Archive mode (recursive, preserves timestamps, file permissions, and symlinks).
    • The --delete flag is NOT used. Any files already sitting in the destination remain untouched.
2. What Happens When Folder Structure Changes in the SOURCE Directory?

Because delete/mirror flags are not enabled, changes to the local source folder structure produce additive accumulation on the destination server:

  • Renaming a Local Folder: If you rename Group1_OldName/ to Group1_NewName/ locally and run Step 33, the destination server will now contain BOTH Group1_OldName/ and Group1_NewName/. The old folder on the server is not deleted or renamed.
  • Deleting Local Files: If you delete intermediate CSVs, old plot PNGs, or failed tests on your workstation, those deleted files will still remain on the destination server from previous uploads.
  • Moving Files Locally: If a file is moved to a subfolder locally, it will be uploaded into the subfolder on the server, but the previous copy at the old path will also remain on the server.
  • Best Practice: If you perform major local restructuring or rename test groups, connect to the destination server and manually delete or archive the outdated folder before re-uploading.
3. What Happens When Folder Structure Changes in the DESTINATION Directory?

If files or directories are altered on the destination server directly:

  • Files/Folders Deleted on Server: If someone deletes files on the server, the next run of Step 33 will see that they are missing and re-copy them fresh from your local source.
  • Folders Renamed on Server: If someone renames a folder on the server (e.g. Server/Group1 → Server/Group1_Archived), Step 33 will treat the original folder as missing and upload Source/Group1 again alongside the renamed one.
  • File Overwrite & Conflict Rules:
    • On Windows: If a destination file was edited on the server and has a newer timestamp than your local file, robocopy's /XO flag skips it and preserves the server version. If the server file is older, it will be overwritten by your local copy.
    • On macOS/Linux: If a destination file has a different modification time or file size, rsync -a will overwrite the destination file with the local source version.
