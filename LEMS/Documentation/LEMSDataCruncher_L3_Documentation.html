LEMSDataCruncher_L3 Documentation

Data Processing Pipeline — Detailed Workflow & File Specifications for Steps 1 through 12

Session Initialization & Folder Selection

When running LEMSDataCruncher_L3.py, you will first choose between:

  • CLI Mode (cli): You are prompted for a root folder_path. The folder must contain UnformattedDataL2FilePaths_DataEntrySheetFilePaths.csv, which links to each group’s DataEntrySheetFilePaths.csv and lists the test paths.
  • GUI Mode (default): You enter the number of test runs and select each test’s Data Entry Form via file picker dialog ([testname]_TE_DataEntryForm.xlsx). The target folder is determined from the directory where the selected file lives.
  • Execution Mode: Choose 1 for Interactive Mode (plots open in Matplotlib, popups prompt for inputs) or 2 for Reprocessing Mode (runs in parallel across worker processes, non-interactive, reads existing parameters).

Step 1 plot raw data

Plots all raw time-series sensor channels against time. Verifies signal continuity, timestamps, and data validity before running calculations.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_RawData.csv Main raw sensor box CSV export containing timestamps, calibration headers, and time-series sensor readings (CO, CO2, PM, temperatures, etc.).
Optional [testname]_FormattedCombinedScaleData.csv If combined fuel scale data was previously generated in Step 3, it is automatically read and included in the time-series plot.
Auto-Created [testname]_rawplots.csv Plot configuration file. If missing, it will be automatically generated with default values.

User Decisions & Inputs Required

1. Channel Selection & Scaling in [testname]_rawplots.csv

When Step 1 runs for the first time, it discovers all plottable channels and writes [testname]_rawplots.csv with Plotted = 0 (disabled). To view specific channels:

  • Open [testname]_rawplots.csv in a text editor or spreadsheet program.
  • Set Plotted to 1 for any channel you want to display (e.g., CO, CO2, PM).
  • Adjust Scale multipliers as needed (e.g., 0.1 or 10) so channels with different magnitudes fit on one graph.
  • (Optional) Assign colors or numeric plot Order (higher values plot on top). Save the file and re-run Step 1.
2. Window Interaction (Interactive Mode 1)

An interactive Matplotlib window opens displaying the graph. The user inspects the raw data curves, zooms/pans as needed, and closes the window to finish the step and return to the main menu.

In Reprocessing Mode (2): Matplotlib runs headless (Agg backend). No user input is required; the image is generated directly.

Output Files Generated

Status Output File Description
Generated [testname]_rawplots.csv Table specifying plottable variables, active flags (Plotted), scale factors, colors, and order.
Generated [testname]_rawplot.png High-resolution image rendering of the raw sensor time-series plot.
Updated [testname]_log.txt & L3_log.txt Log files updated with execution status, timestamps, and error messages (if any).

Step 2 load data entry form

Parses the test metadata, fuel parameters, moisture contents, and thermal mass data from the test data entry sheet and flattens them into a structured key-value CSV file used by all subsequent calculation steps.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_TE_DataEntryForm.xlsx (or .csv) The completed test spreadsheet containing named input cells/columns for stove configuration, fuel specifications, tare weights, start/end times, and test phases.

User Decisions & Inputs Required

Pre-Run Data Integrity Check

Step 2 requires no interactive terminal prompts or popup dialogs while executing. However, the user must ensure that the Excel Data Entry Form is completely filled out prior to execution:

  • All required named input cells must contain valid numbers (e.g., initial/final pot water weights, fuel moisture percentage, wood mass, tare weights).
  • Phase time markers and background durations must be properly entered.
  • The file must not be locked or open in Microsoft Excel with unsaved changes.

Output Files Generated

Status Output File Description
Generated [testname]_EnergyInputs.csv Standardized 4-column CSV (variable, units, value, uncertainty) containing all parsed inputs from the spreadsheet for use in energy and emission calculations.
Updated [testname]_log.txt & L3_log.txt Appends loading confirmation and output path.
Tip: If you change any weights, fuel parameters, or times in the Excel spreadsheet later, you must re-run Step 2 so [testname]_EnergyInputs.csv reflects the new values before running downstream calculation steps.

User Decisions & Inputs Required

Sensirion Fan & Flow Configuration (Interactive Mode 1)

If [testname]_SenserionRawData.csv exists and [testname]_SenserionInputs.csv has not yet been created, popup dialogs (easygui.multenterbox) prompt the user for the following decisions:

  • Fan Flow Assignment: For each detected flow channel, specify whether it is Primary or Secondary (used to calculate total airflow).
  • Orifice / Duct Geometry: For each flow channel, enter the duct/hole diameter in cm ([name]_dia) and the number of holes ([name]_num) to calculate air velocity.
  • Thermocouple Channels: Enter descriptive names for each thermocouple sensor (TC channels).
  • Differential Pressure Channels: Enter descriptions/assignments for each deltaP channel.

In Reprocessing Mode (2): The script expects [testname]_SenserionInputs.csv to already exist from a previous run and loads it automatically without dialog prompts.

Automatic Scale Merging

If both [testname]_FormattedScaleData.csv and [testname]_FormattedAdamScaleData.csv are generated, the script automatically synchronizes their timestamps and merges them into a combined scale output. No user decision is required.

Step 4 calculate energy metrics

Calculates ISO 19867-1 thermal performance and energy metrics using input parameters extracted in Step 2. Evaluates dry fuel consumption, char production, net useful energy delivered to water, thermal efficiency, burning rates, and turn-down ratios across individual test phases and the overall test.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_EnergyInputs.csv Standardized inputs table created in Step 2 (or updated via Step 0 template). Contains water boiling point, net calorific values, fuel moisture content, tare/pot masses, initial/final fuel masses, and phase timestamps.

User Decisions & Inputs Required

Automated Computation & Input Validation

Step 4 executes completely automatically without interactive popup dialogs or terminal prompts. However, the user must ensure:

  • Input Verification: If any fuel moisture, pot water weights, fuel mass, or phase timestamps were updated in the spreadsheet, Step 2 must be re-run first to update [testname]_EnergyInputs.csv.
  • Phase Timestamps: Phase start and end times must be valid and chronological in the input file so that phase durations and burn rates can be computed without math errors.

Output Files Generated

Status Output File Description
Generated [testname]_EnergyOutputs.csv Full CSV table containing ISO 19867-1 thermal efficiency (%), useful energy delivered (kJ), dry fuel consumed (kg), char produced (kg), burning rates (g/min, kg/hr), fire power (kW), and turn-down ratios for each phase (L1, hp, mp, lp, L5) and the full test, along with uncertainty estimates.
Updated [testname]_log.txt & L3_log.txt Appends calculation completion timestamps, loaded inputs path, and any calculation exceptions.
Note: [testname]_EnergyOutputs.csv is a fundamental prerequisite for subsequent reporting, custom comparison tables (Steps 15, 19, 30), and multi-test plotting (Steps 23–28).

Step 5 adjust sensor calibrations

Applies revised calibration polynomials ($A, B, C, D$) to raw sensor signals and re-executes firmware equations for supported sensor box models. Useful when instruments are post-calibrated or when hardware calibration coefficients need to be corrected after testing.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_RawData.csv Raw sensor box time-series data file containing sensor channels and embedded calibration coefficients ($A, B, C, D$) in its header.
Optional / Auto-Created [testname]_Header.csv Standalone calibration table extracted from the raw data header. If not present, the script auto-creates it using the coefficients embedded in [testname]_RawData.csv.
Optional / Auto-Created [testname]_SensorboxVersion.csv Configuration file storing the sensor box hardware/firmware model identifier (e.g., SB: SB4003.16). Generated or updated based on user input.

User Decisions & Inputs Required

1. Edit Calibration Coefficients in [testname]_Header.csv (Interactive Mode 1)

A popup message box displays:

“Open the Header input file and edit the desired calibration parameters if needed: [path to Header.csv]. Save and close the Header input file then click OK to continue.”

  • User Decision: If sensor calibrations have changed, open [testname]_Header.csv in a text editor or spreadsheet, update polynomial coefficients ($A, B, C, D$) for any sensor channel (e.g. CO, CO2, sample train flow), save the file, and click OK.
  • If no calibration adjustments are needed, simply click OK without editing.
2. Sensorbox Firmware Version Selection (Interactive Mode 1)

An entry dialog prompts:

“Enter sensorbox firmware version. Firmware version may be found labeled on the box or printed in the data under version.”

  • User Decision: Confirm or enter the sensor box firmware version (defaults to the version found in the header or SB4003.16).
  • Supported versions include: SB4002, SB4003, SB4004, SB4005, SB4007, SB4008, SB4010–SB4018, SB2041, SB3001–SB3016, and Possum2.
  • The entered version is saved to [testname]_SensorboxVersion.csv for future automated runs.
3. Visual Inspection of Recalculated Channels (Interactive Mode 1)

If any calibration coefficients changed and caused channels to be recalculated:

  • A dialog notifies: “The following plots show the effect of the recalculation. Close the plots to continue.”
  • An interactive Matplotlib figure window displays overlay plots of [channel] old vs. [channel] new across all sample points.
  • User Decision: Visually verify the calibration adjustments, inspect differences, and close the plot window to return to the main menu.

In Reprocessing Mode (2): Reads existing calibration parameters from [testname]_Header.csv and firmware version from [testname]_SensorboxVersion.csv headlessly without popup dialogs or figure displays.

Output Files Generated

Status Output File Description
Generated [testname]_Header.csv Isolated calibration header file storing polynomial coefficients ($A, B, C, D$).
Generated [testname]_SensorboxVersion.csv Record of the selected sensor box firmware version.
Generated [testname]_RawData_Recalibrated.csv Recalculated time-series data file with updated sensor values, ready for response time shifting in Step 6. (If no calibrations were changed, contains identical readings to the raw file).
Updated [testname]_log.txt & L3_log.txt Logs which calibration coefficients were modified (e.g., $A_{\text{old}} \to A_{\text{new}}$) and which data series were recalculated.

Step 6 correct for response times

Shifts individual time-series sensor channels forward or backward along the time axis to compensate for sample line transit delays and differing sensor response times (e.g. aligning electrochemical or NDIR gas sensors with optical particulate sensors).

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_RawData_Recalibrated.csv Recalibrated time-series CSV produced by Step 5. (If Step 5 was skipped, a copy of [testname]_RawData.csv named with this pattern must be present).
Optional / Auto-Created [testname]_TimeShifts.csv Channel time shift configuration table. If not already present in the folder, the script automatically creates it with 0 seconds for every channel.

User Decisions & Inputs Required

Configuring Time Delay Offsets (Interactive Mode 1)

A multi-entry dialog (easygui.multenterbox) titled Gitrdone opens displaying each sensor channel (excluding light sensor AS channels and time columns) with its current shift in seconds.

User Decisions: Enter the number of integer seconds to shift each data channel:

  • Negative Values (e.g. -8): Shifts the data series back in time (advances signal; removes leading points and pads the end). Use this if a gas sensor lags behind real-time combustion events due to long sample tubing.
  • Positive Values (e.g. +5): Shifts the data series forward in time (delays signal; pads the front and truncates the end).
  • Zero (0): Leaves the channel unshifted.

Clicking OK applies the shift and updates [testname]_TimeShifts.csv.

Manual Alternative: You can open and edit [testname]_TimeShifts.csv directly in a text editor or spreadsheet prior to running Step 6.

In Reprocessing Mode (2): Bypasses the dialog and automatically applies shift values already saved in [testname]_TimeShifts.csv.

Output Files Generated

Status Output File Description
Generated [testname]_TimeShifts.csv Table containing time delay values in seconds for each sensor channel.
Generated [testname]_RawData_Shifted.csv Time-aligned time-series data file. This file serves as the direct input for Step 7 (background subtraction).
Updated [testname]_log.txt & L3_log.txt Logs each channel shifted, shift direction (up/down), and the number of seconds applied.

Step 7 subtract background

Determines ambient pollutant baselines before and after the test, inspects signal drift, and subtracts background levels from time-series sensor signals (CO, CO2, PM, VOC, CH4, and differential pressures). Generates phase-by-phase averages and background-subtracted time-series data.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_RawData_Shifted.csv Time-aligned time-series sensor data produced by Step 6.
Required [testname]_EnergyInputs.csv Test inputs table from Step 2, providing initial phase timestamps.
Optional / Auto-Created [testname]_PhaseTimes.csv Start and end timestamps for pre-background (prebkg), test phases (L1, hp, mp, lp, L5), and post-background (postbkg).
Optional / Auto-Created [testname]_BkgMethods.csv Channel-specific background subtraction method and numeric offset specification (e.g. prepostlin,0).
Optional / Auto-Created [testname]_UCInputs.csv Measurement uncertainty configuration table (absolute and relative uncertainties).

User Decisions & Inputs Required

1. Initial Background Times Prompt (Interactive Mode 1)

If [testname]_PhaseTimes.csv does not exist, an entry dialog opens asking for start and end times for pre-test and post-test background periods (start_time_prebkg, end_time_prebkg, start_time_postbkg, end_time_postbkg). Default values are suggested based on file start/end times.

2. Interactive Phase Time & Method Refinement Loop (Interactive Mode 1)

Two Matplotlib figures open displaying time-series curves (CO, CO2, PM) with vertical phase boundary markers. An interactive loop prompts the user through two dialogs:

  • Edit Phase Times Dialog: The user zooms into the plot to locate stable, flat baseline regions before stove ignition and after burnout, then enters refined start and end times for prebkg, test phases, and postbkg.
  • Edit Background Subtraction Methods Dialog: For each background channel, enter method,offset:
    • prepostlin: (Recommended) Linear interpolation between mean pre-background and post-background values to correct for instrument baseline drift.
    • prepoststave: Simple mean of pre- and post-background periods.
    • pre: Uses pre-test background average only.
    • post: Uses post-test background average only.
    • none: Disables background subtraction for that channel.
    • offset: Numeric value added to data after subtraction (normally 0).

Closing the plot windows accepts the current configuration and finishes the step.

In Reprocessing Mode (2): Bypasses interactive dialogs and plots, reading parameters directly from [testname]_PhaseTimes.csv and [testname]_BkgMethods.csv.

Output Files Generated

Status Output File Description
Generated [testname]_TimeSeries.csv Full-length background-corrected time-series data file across all channels and phases. Primary input for Step 10.
Generated [testname]_Averages.csv Table containing mean values and standard deviations for every data channel during each phase.
Generated [testname]_PhaseTimes.csv Configuration file storing validated start and end times for all phases and background periods.
Generated [testname]_BkgMethods.csv & [testname]_BkgOutputs.csv Methods table and summary of background values subtracted for each channel.
Generated [testname]_subtractbkg1.png & [testname]_subtractbkg2.png High-resolution diagnostic plot figures displaying background baseline curves and phase cuts.
Generated [testname]_UCInputs.csv Measurement uncertainty settings per channel.

Step 9 calculate gravimetric PM

Calculates total particulate matter (PM) mass collected, sample duration, volumetric flow volume, and gravimetric PM concentration ($\text{mg}/\text{m}^3$) from physical filter weighings across each test phase.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_Averages.csv Phase average concentrations and flow rates produced in Step 7.
Required [testname]_PhaseTimes.csv Phase start and stop timestamps from Step 7.
Required [testname]_EnergyOutputs.csv Energy metrics from Step 4 (provides default sample flow rates if available).
Optional / User Created [testname]_GravInputs.csv Table containing physical filter IDs, pre-test tare weights, and post-test gross weights. Created or edited during this step.

User Decisions & Inputs Required

1. Gravimetric Flow Train Channel Selection (Interactive Mode 1)

If [testname]_GravInputs.csv does not exist, a multi-choice dialog (easygui.multchoicebox) prompts:

“Select Grav Channels Used. For 3000 series, select the appropriate sensorbox version...”

  • User Decision: Choose which filter flow trains were sampled during the test (e.g. A, B, SB4004_A, SB4007_A, SB3001_A, etc.). Multiple channels can be selected simultaneously.
2. Filter Weights & Sampling Period Entry (Interactive Mode 1)

A multi-entry dialog (easygui.multenterbox) prompts for filter weighing data for each selected channel and phase:

  • filterID_[channel]_[phase]: Filter identification label (e.g. F-1024).
  • taremass_[channel]_[phase]: Conditioned clean filter weight before testing in grams (g).
  • grossmass_[channel]_[phase]: Conditioned loaded filter weight after sampling in grams (g).
  • Start and end timestamps (pre-populated with phase times from Step 7).
  • Sample train flow rate (GravFlo1, GravFlo2 in L/min; default 16.7 L/min).

In Reprocessing Mode (2): Automatically reads saved weighings directly from [testname]_GravInputs.csv.

Output Files Generated

Status Output File Description

Generated [testname]_GravOutputs.csv Gravimetric metrics table: net particulate mass ($m_{\text{filter}} = \text{gross} - \text{tare}$ in mg), sample volume ($V$ in $\text{m}^3$), duration, and PM concentration ($\text{mg}/\text{m}^3$) per phase and total test.
Updated [testname]_log.txt & L3_log.txt Logs net filter masses, flow volumes, and PM concentrations.

Step 10 calculate emission metrics

Calculates ISO 19867-1 emissions metrics, mass emission rates ($g/\text{min}$), emission factors per dry fuel mass ($g/\text{kg}$), emission factors per useful energy delivered ($g/\text{MJ}$), and optical-to-gravimetric calibration factors. Produces consolidated master data sheets and formatted summary reports.

Target Folder File Prerequisites

User Decisions & Inputs Required

Dilution Tunnel & PM Optical Parameters Dialog (Interactive Mode 1)

A multi-entry dialog prompts user to confirm or edit dilution tunnel parameters:

  • MSC_default: Mass Scattering Cross-section in $m^2/g$ (default 3.0). Used to convert optical light scattering to real-time PM2.5 mass when gravimetric filters are unavailable or incomplete.
  • flowgrid_cal_factor: Flow grid calibration multiplier determined from pitot velocity traverses (default 1.0 at sea level; adjusted for altitude/density).
  • factory_flow_cal: Factory calibration factor determined by dilution tunnel diameter (default 15.3 for standard 6-inch tunnel, 62.8 for 12-inch tunnel).
  • static_pressure_dil_tunnel: Dilution tunnel static pressure in inches of water (default 0.75 inH2O).

In Reprocessing Mode (2): Automatically uses parameters stored in [testname]_EmissionInputs.csv. If the user opted to skip time-series recalculation at launch, pre-existing _EmissionOutputs.csv is reused to accelerate processing.

Target Folder File Prerequisites

Steady Fuel Burn Period Trimming (Interactive Mode 1)

For each space heating test phase (La, Lb, hp, mp, lp, L5):

  • An interactive Matplotlib figure displays the fuel scale weight curve alongside stack CO2 concentrations.

  • User Decision: Adjust start and end times to select a steady evaluation window where fuel weight decreases steadily and monotonically (excluding fuel reload disturbances, door openings, or scale mechanical noise).
  • The graph refreshes to display the cut curve. Closing the dialog accepts the cut window, updates [testname]_ThermalEfficiencyCutTimes_[phase].csv, and saves the diagnostic image.

In Reprocessing Mode (2): Bypasses interactive trimming and loads existing cut times from [testname]_ThermalEfficiencyCutTimes_[phase].csv.

Step 12 calculate averages from a specified cut period

Isolates and evaluates a custom sub-period (averaging period or “cut period”) within any selected test phase (e.g., L1, hp, mp, lp, L5). Computes representative average pollutant concentrations, emission rates, and performance metrics over a stable steady-state window without being skewed by refueling spikes, ignition transients, or phase burn-down tails.

Target Folder File Prerequisites

Status File Name Pattern Description & Purpose
Required [testname]_TimeSeriesMetrics_[phase].csv Phase-specific real-time metrics time-series generated during Step 10 (e.g. _TimeSeriesMetrics_hp.csv, _TimeSeriesMetrics_lp.csv).
Required [testname]_EnergyOutputs.csv Energy metrics and fuel properties from Step 4.
Required [testname]_GravOutputs.csv Gravimetric PM metrics from Step 9.
Required [testname]_PhaseTimes.csv Phase start and stop timestamps from Step 7.
Optional / Auto-Created [testname]_AveragingPeriod_[phase].csv Table storing the defined start and end timestamps (start_time_[phase], end_time_[phase]) for the cut period.
Optional Auxiliary Formatted Sensor Files _FormattedScaleData.csv, _FormattedIntScaleData.csv, _FormattedAdamScaleData.csv, _FormattedCombinedScaleData.csv, _FormattedNanoscanData.csv, _FormattedTEOMData.csv, _FormattedSenserionData.csv, _FormattedOPSData.csv, _FormattedPicoData.csv (if used).

User Decisions & Inputs Required

1. Phase Selection (Interactive Mode 1)

A choice dialog (easygui.choicebox) titled Gitrdun opens asking:

“Select which phases will be graphed” with choices: L1, hp, mp, lp, L5.

  • User Decision: Select the test phase for which you want to isolate a cut period.
2. Interactive Cut Period Trimming Loop (Interactive Mode 1)

An interactive Matplotlib figure displays the full-phase real-time curve (e.g., CO2 or CO2v in red) overlaid with the currently cut period (in green).

  • A multi-entry dialog (easygui.multenterbox) titled Gitrdone prompts with start_time_[phase] and end_time_[phase].
  • User Decision: Zoom in on the graph to identify the most stable, representative combustion period (avoiding door openings, fuel reload disturbances, or erratic burn behavior). Enter adjusted start and end timestamps and click OK.
  • The plot refreshes to show the updated cut period. Repeat until satisfied.
  • Click Cancel (or close the plot) to confirm the cut period, save the diagnostic image, and finalize calculations.

In Reprocessing Mode (2): Bypasses interactive dialogs and executes across all available phases (L1, hp, mp, lp, L5) in parallel, automatically reading pre-saved cut timestamps from [testname]_AveragingPeriod_[phase].csv.
